# C04: Infrastructure, Configuration & Deployment Security

> **Source:** [`1.01-dev/en/0x10-C04-Infrastructure.md`](https://github.com/OWASP/AISVS/blob/main/1.01-dev/en/0x10-C04-Infrastructure.md)
> **Requirements:** 14 | **Sections:** 3

## Control Objective

AI-specific infrastructure components must be hardened against model theft, data leakage, and cross-tenant contamination. This chapter covers AI workload sandboxing, AI accelerator hardware security, and edge/distributed AI deployment security. General infrastructure security controls (container hardening, network segmentation, secrets management, CI/CD pipeline security) are covered by ASVS, CIS Benchmarks, and NIST SP 800-53, and are not repeated here. AI-specific supply chain controls are covered in C6.

## Threat Landscape

Known attacks, real-world incidents, and threat vectors relevant to this chapter:

- **AI gateway exploited in the wild — LiteLLM MCP command injection (June 2026 KEV)** — CVE-2026-42271 (CVSS 8.8, fixed in LiteLLM 1.83.7; GitHub advisory April 25, 2026) let any caller holding a valid API key — any role — POST an MCP stdio-transport configuration with attacker-controlled `command` and `env` fields to the proxy's MCP preview endpoints, which spawned the command as a subprocess with the proxy's privileges. CISA added it to the [Known Exploited Vulnerabilities catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) on June 8, 2026 with a June 22 remediation deadline — confirmation that AI gateways sitting in front of model-serving fleets are being exploited, not just researched. See the [GitHub advisory](https://github.com/BerriAI/litellm/security/advisories/GHSA-v4p8-mg3p-g94g). For the second time in 2026 (after TeamPCP), LiteLLM's reach — Wiz reports it present in 36% of cloud environments in its data, a presence figure rather than a count of exposed deployments — means a single proxy flaw can touch many deployments.
- **vLLM June 2026 advisory cluster — auth bypass, build-time dependency confusion, pin decay** — Three advisories in nine days. [CVE-2026-48746](https://github.com/vllm-project/vllm/security/advisories/GHSA-94f4-hr76-p5j6) (CVSS 9.1, June 2): the API-key middleware reconstructs URLs from the untrusted Host header, so special characters desync the checked path from the FastAPI-routed path and requests reach protected endpoints without `VLLM_API_KEY` (fixed in 0.22.0; RFC-conforming reverse proxies like nginx block the malformed Host header). [GHSA-jrf6-vqxq-pjv2](https://github.com/vllm-project/vllm/security/advisories/GHSA-jrf6-vqxq-pjv2) (CVSS 8.8, June 9): the official Dockerfile installed `flashinfer-jit-cache` via `--extra-index-url` with `UV_INDEX_STRATEGY=unsafe-best-match` while the name was unregistered on PyPI — a squatted package would execute as root during image build (a third party did register the name with a non-malicious test package, which PyPI quarantined) (fixed in 0.22.1). [CVE-2026-47155](https://github.com/vllm-project/vllm/security/advisories/GHSA-3ww4-5jv9-j5gm) "Artifact Pin Decay" (June 10): `--revision`/`--code-revision` pins are not propagated to secondary artifacts — dynamic code modules, GGUF loaders, image processors, cross-subfolder weights — so "pinned" deployments silently load unpinned code and weights from default branches.
- **vLLM resource amplification and malformed embeddings (April–June 2026)** — Three advisories show why byte-size and rate limits alone are incomplete. [CVE-2026-34755](https://github.com/vllm-project/vllm/security/advisories/GHSA-pq5c-rjhq-qp7p) let one `video/jpeg` data URL bypass the normal frame limit and expand thousands of compressed frames into an out-of-memory crash; [CVE-2026-34756](https://github.com/vllm-project/vllm/security/advisories/GHSA-3mwp-wvh9-7528) let an extreme OpenAI-compatible `n` value synchronously clone requests until the event loop and heap were exhausted. Both are fixed upstream in 0.19.0. [CVE-2026-56340](https://nvd.nist.gov/vuln/detail/CVE-2026-56340) (GitHub advisory January 2026, CVE assigned June 2026) continued an earlier incomplete fix: when prompt embeddings were enabled, missing sparse-tensor invariant checks accepted negative or out-of-bounds indices, allowing crashes or resource exhaustion with potential memory corruption; 0.13.0 contains the root-cause fix. Inference gateways need semantic budgets on decoded media count and output multiplicity, while the server must validate complete tensor shapes and index bounds before allocating GPU or host memory.
- **vLLM multimodal pipeline RCE and SSRF-bypass (Feb–Mar 2026)** — Two earlier vLLM flaws round out the multimodal/input-fetch attack surface that the June cluster sits on top of. [CVE-2026-22778](https://www.kodemsecurity.com/resources/cve-2026-22778-critical-remote-code-execution-in-vllm-multimodal-inference) (CVSS 9.8, disclosed Feb 2, 2026; affects 0.8.3–0.14.0, fixed in 0.14.1) is a chained exploit: a malicious *video* URL sent to a vLLM multimodal endpoint leaks memory via PIL/OpenCV error messages to defeat ASLR, then drives a heap overflow in the JPEG2000 decoder (OpenCV/FFmpeg) into remote code execution on the GPU cluster — model-server compromise straight through the inference API, no auth bug required. [CVE-2026-25960](https://www.esecurityplanet.com/artificial-intelligence/critical-vllm-flaw-puts-ai-systems-at-risk-of-remote-code-execution/) (CVSS 7.1, disclosed Mar 9, 2026) is a parser differential between `urllib3` and `yarl` inside `load_from_url_async` that bypasses vLLM's own SSRF protection — the same class as the LMDeploy `load_image()` SSRF, and a reminder that framework-internal allowlist parsing diverges from what the HTTP client actually fetches. Both reinforce that 4.1.1 sandboxing and SSRF egress filtering must wrap the *entire* inference process, including its media-decode and URL-fetch paths, not just the weight loader.
- **Model-config code execution despite `trust_remote_code=False` (June 2026)** — Hugging Face Transformers [CVE-2026-4372](https://www.csoonline.com/article/4181094/hugging-face-transformers-rce-flaw-enables-stealthy-compromise-via-ai-model-configs.html) (affects 4.56.0–5.2.x, fixed in 5.3.0, silently patched March 3 and publicly disclosed June 4 by Pluto Security): injecting `_attn_implementation_internal` into a model's `config.json` makes Transformers — with the optional `kernels` package installed — fetch and execute code from an attacker-controlled kernel repo during model load, bypassing `trust_remote_code=False`. OpenMed CVE-2026-47117 (CVSS 9.8, CVE published June 2, fixed in 1.5.2) made the same class pre-auth: its PII-filter substring-matched the user-supplied `model_name` and loaded the matching Hugging Face repo with `trust_remote_code` enabled. Both reinforce C4.1.2's point that the *configuration* and *loader path* of a model artifact are code-execution surfaces, not just the serialized weights.
- **Container-escape KEV additions (May–June 2026)** — CISA added CVE-2022-0492 (Linux cgroups `release_agent` container escape) to KEV on June 2, 2026, and Langflow CVE-2025-34291 (origin validation, distinct from the March CVE-2026-33017) on May 21, 2026 — both confirmed exploited in the wild and both squarely in C4.1 sandbox-isolation territory: a four-year-old kernel escape is actively used against containerized workloads.
- **Triton authentication bypass and DALI flaws (May 2026)** — NVIDIA's [May 2026 Triton bulletin](https://nvidia.custhelp.com/app/answers/detail/a_id/5828/~/security-bulletin%3A-nvidia-triton-inference-server---may-2026) patches eight issues, headlined by CVE-2026-24207 (CVSS 9.8, CWE-288) — an unauthenticated authentication-bypass that gives remote code execution, privilege escalation, data tampering, denial of service, and information disclosure against a network-reachable Triton instance. Three issues land in the DALI backend (CVE-2026-24213/24214/24215, two at CVSS 8.0), tightening the noose on the pre-processing pipeline that sits in front of model inference. Fixed in Triton r26.03; older r26.02 deployments need an urgent upgrade.
- **Triton compressed-input and use-after-free denial of service (June 2026)** — NVIDIA's [June 2026 Triton bulletin](https://github.com/NVIDIA/product-security/blob/main/2026/5848/5848.md), revised July 1, adds [CVE-2026-24264](https://nvd.nist.gov/vuln/detail/CVE-2026-24264) (CVSS 7.5, improper handling of highly compressed data) and [CVE-2026-24266](https://nvd.nist.gov/vuln/detail/CVE-2026-24266) (CVSS 5.9, use after free). Both are remotely reachable without privileges or user interaction and can deny serving availability; releases through 26.03 are affected and 26.04 is the fixed baseline. This reinforces that sandboxing alone does not preserve inference availability: front ends also need compressed-body limits, request budgets, health-based failover, and a tested patch path.
- **SGLang pickle-over-ZMQ revival (May 2026)** — Published May 18, 2026, CVE-2026-7301 (CVSS 9.8) shows the SGLang multimodal scheduler ROUTER socket binding to `0.0.0.0` and calling `pickle.loads()` on inbound messages — unauthenticated RCE against any internet-reachable SGLang deployment. CVE-2026-7304 (CVSS 9.8) chains in when `--enable-custom-logit-processor` is on, this time via `dill.loads()`. CERT/CC's [VU#777338](https://kb.cert.org/vuls/id/777338) records no patch and no vendor statement as of its May 18 disclosure (vendor notified April 2, 2026); the safest position remains keeping SGLang off the network or fronting it with a network policy that blocks ZMQ ports. It follows the March 2026 SGLang pickle disclosures in VU#665416 (CVE-2026-3059/3060, which CERT/CC lists as addressed in 0.5.10) — the C4.1.2 deserialization control is doing nothing if the framework calls `pickle.loads()` on raw socket bytes.
- **AI framework RCE via workflow platforms** — CVE-2026-33017 (CVSS 9.3, March 2026) in Langflow allows unauthenticated remote code execution via a single HTTP POST to the public flow build endpoint. Attacker-controlled Python code is passed directly to `exec()` without sandboxing, granting access to environment variables, API keys for OpenAI/Anthropic/AWS, and connected databases. CISA added it to KEV within 8 days. Exploited in the wild within 20 hours of disclosure.
- **LMDeploy SSRF as inference-engine pivot (April 2026)** — CVE-2026-33626 in InternLM's LMDeploy let attackers turn the vision-language image loader (`load_image()` in `lmdeploy/vl/utils.py`) into a generic HTTP SSRF primitive. No hostname resolution check, no private-network blocklist. Sysdig saw the first in-the-wild exploitation 12 hours 31 minutes after the GitHub advisory landed — over an eight-minute window the attacker enumerated AWS IMDS, Redis on 127.0.0.1:6379, MySQL on 127.0.0.1:3306, an internal admin HTTP service, and an out-of-band DNS exfiltration endpoint, all through a vision-LLM chat completions endpoint. Fixed in v0.12.3. SSRF defenses (`169.254.0.0/16` egress block, allowlisted hostname pattern, separate egress identity from the inference service identity) belong in every model server deployment guide.
- **Cascading supply chain compromise (TeamPCP)** — In March 2026, the TeamPCP threat actor compromised Aqua Security's Trivy scanner (CVE-2026-33634, CVSS 9.4) by force-pushing 76 malicious version tags in the trivy-action GitHub Action and publishing poisoned Docker Hub images. The attack cascaded to LiteLLM (malicious PyPI packages 1.82.7/1.82.8) and Checkmarx KICS. Wiz Research found LiteLLM present in 36% of monitored cloud environments. Microsoft published emergency detection guidance; BerriAI engaged Mandiant for incident response.
- **Kubernetes-native AI operator command injection** — CVE-2026-34940 in KubeAI showed how model-serving control planes can become execution surfaces. Unsanitized model URL components from a `Model` custom resource were interpolated into an Ollama `bash -c` startup probe, letting users with create/update rights on Model CRDs execute commands inside model server pods. The practical controls are to upgrade to KubeAI 0.23.2 or later, restrict Model CRD writers, enforce admission validation for model URLs, and review startup/readiness/liveness probes as part of C4.1 sandbox validation.
- **Container escape via GPU toolkits** — Critical vulnerabilities in NVIDIA Container Toolkit (CVE-2024-0132, CVE-2025-23266 "NVIDIAScape") allow AI workloads to break container isolation and gain root on the host. Press coverage of Wiz's July 2025 disclosure attributed to Wiz a figure of 37% of cloud environments affected; Wiz's current blog post does not state it, so treat it as unverified.
- **GPU side-channel attacks** — NVBleed (March 2025) demonstrated a contention-based NVLink covert channel above 70 Kbps and side-channel leakage that also worked across cloud VMs, while BarraCUDA showed electromagnetic side-channel recovery of neural-network parameters from an NVIDIA Jetson Nano. Separate research (Veiled Pathways) found four GPU-uncore leakage sources that work under MPS mode, plus a PCIe covert channel across MIG instances.
- **GPU memory bit-flip attacks** — GPUHammer (USENIX Security 2025) demonstrated practical Rowhammer attacks against GDDR6 memory on NVIDIA GPUs. In the authors' proof of concept, a single bit flip degraded a victim DNN's accuracy from 80% to 0.1% on an RTX A6000 (GDDR6), and the attack lets one GPU user tamper with another user's data in shared, time-sliced environments. Enabling ECC mitigates it, at up to about 10% inference slowdown in the authors' A6000 tests; the authors saw no flips on an RTX 3080 or A100 and note that H100 (HBM3) and RTX 5090 (GDDR7) have on-die ECC that likely masks single-bit flips.
- **Supply chain compromise of ML frameworks** — CVE-2025-32434 (CVSS 9.3) proved that PyTorch's `weights_only=True` could be bypassed for RCE. Three PickleScan zero-day bypasses (CVE-2025-10155/56/57) let malicious pickle models evade the scanner Hugging Face relies on.
- **Secrets leakage from AI pipelines** — A November 2025 Wiz study found 65% of the Forbes AI 50 companies it scanned (those with a GitHub presence) had leaked verified secrets on GitHub, often buried in deleted forks, gists, and org members' repositories, in files such as `.py`, `.ipynb`, `.env`, and `mcp.json`. One Hugging Face token found in a deleted fork could have exposed access to about 1,000 private models.
- **TEE bypass attacks** — TEE.Fail (October 2025) extracted attestation keys to break Intel SGX and TDX attestation and AMD SEV-SNP with Ciphertext Hiding, using DDR5 memory bus interposition hardware the authors estimate at under $1,000, undermining confidential computing assumptions.
- **Linux kernel Dirty Frag (May 2026)** — CVE-2026-43284 (CVSS 7.8) and CVE-2026-43500 (CVSS 7.8) are paged page-cache write primitives in the IPsec ESP (`xfrm`) and RxRPC subsystems. Disclosed May 8, 2026 after the embargo broke, the chain gives local root; Wiz lists Ubuntu, RHEL, CentOS Stream, AlmaLinux, Fedora, and openSUSE (and potentially OpenShift) as known or likely vulnerable. Microsoft reported limited in-the-wild post-compromise activity. Hardened Kubernetes nodes with default seccomp profiles raise the bar (the trigger needs `CAP_NET_ADMIN`), but AI workloads that grant elevated network capabilities — sidecars handling RDMA setup, model fetchers, training-job init containers — are still in scope. Patching was staggered: no official patches existed at publication, some distributions (for example AlmaLinux) had early kernels, and Microsoft noted on May 8 that CVE-2026-43500 patches were not yet available.
- **Container runtime breakout (runC)** — Three critical runC vulnerabilities disclosed in November 2025 (CVE-2025-31133, CVE-2025-52565, CVE-2025-52881) affect all Docker, Kubernetes, containerd, and CRI-O deployments. CVE-2025-31133 exploits a mount race condition in maskedPaths to redirect writes to `/proc/sys/kernel/core_pattern`, achieving container escape. CVE-2025-52565 abuses a timing window where `/dev/console` is mounted before security protections are applied. CVE-2025-52881 bypasses Linux Security Module labels via shared mount race conditions. All three are deliverable through untrusted container images — a realistic attack vector for AI workloads that routinely pull models and dependencies from external registries. Fixed in runC 1.2.8 / 1.3.3 / 1.4.0-rc.3.
- **ShadowMQ — copy-paste RCE across inference frameworks** — In November 2025, Oligo Security disclosed ShadowMQ, a systemic pattern where Meta's Llama Stack RCE (CVE-2024-50050) propagated by direct copy-paste into NVIDIA TensorRT-LLM, vLLM, SGLang, and Modular Max Server. All of them called ZeroMQ's `recv_pyobj()` over unauthenticated TCP sockets, triggering `pickle` deserialization on attacker input. Exploitation yields arbitrary code execution on GPU clusters — exfiltration of model weights, lateral movement, or GPU cryptomining. Fixed in Llama Stack ≥ 0.0.41, TensorRT-LLM 0.18.2, and Modular Max v25.6; vLLM's CVE-2025-30165 was not patched (the V0 engine it affects has been off by default since 0.8.0), and Sarathi-Serve was reported unpatched. This is a direct C4.1.2 case study: the frameworks that serve models were themselves loading attacker input through unsafe deserialization paths.
- **Inference server takeover chain** — CVE-2025-23319, CVE-2025-23320, and CVE-2025-23334 in NVIDIA Triton Inference Server (disclosed Aug 2025 by Wiz Research) chain into unauthenticated RCE against a production model-serving platform. Separately, the first Pwn2Own AI category (Berlin 2025) included Triton, Redis, and Chroma as targets — seven of twenty-eight competition vulnerabilities came from the AI bracket. Trend Micro's 2026 projection (a vendor forecast, not a count) puts AI CVEs at 2,800–3,600 (up from 2,130 in 2025), with inference servers, model-hosting platforms, and agentic systems driving the growth.
- **Inference server availability and model-config exposure** — NVIDIA's March and April 2026 Triton bulletins added eight more network-reachable flaws after the August 2025 takeover chain. March fixed CVE-2025-33238, CVE-2025-33254, and CVE-2026-24158 (large compressed HTTP payload denial of service) in 26.01; April fixed CVE-2026-24146/24173/24174/24175 denial-of-service flaws and CVE-2026-24147 model-configuration upload information disclosure/DoS in r26.02. Treat inference endpoints as service infrastructure: cap request and output sizes, gate model repository writes, restrict model-configuration upload paths, and rehearse rollback before disclosure windows.
- **Outbound-request abuse of model servers** — GreyNoise honeypots recorded sessions between October 2025 and January 2026 that injected malicious registry URLs into Ollama's model-pull function to make servers send requests to attacker infrastructure ([GreyNoise](https://www.greynoise.io/blog/threat-actors-actively-targeting-llms)); GreyNoise assessed the activity as probably researchers or bug-bounty hunters.
- **Edge model extraction** — On-device models shipped without protection can be pulled from mobile apps with standard reverse-engineering tools (see C4.3 for details).

### Inference Server Hardening Checks

- Track inference-server PSIRT bulletins separately from base container and GPU driver patching; Triton moved from the August 2025 RCE chain through monthly March–September 2026 bulletins — each one network-reachable, each one shifting the operational baseline. The [June bulletin](https://github.com/NVIDIA/product-security/blob/main/2026/5848/5848.md) made 26.04 the fixed baseline after compressed-input and use-after-free denial-of-service flaws in releases through 26.03, but later bulletins moved it again: [July](https://github.com/NVIDIA/product-security/blob/main/2026/5853/5853.md) (r26.05, including an authentication bypass, CVE-2026-47481), [August 18](https://github.com/NVIDIA/product-security/blob/main/2026/5865/5865.md) (26.06, including path traversal, CVE-2026-47627, CVSS 9.8) and [September 8](https://github.com/NVIDIA/product-security/blob/main/2026/5875/5875.md) (r26.07).
- Put explicit limits in front of model-serving HTTP/gRPC endpoints: compressed request body size, decoded media frame count, output multiplicity and tensor count, decompression ratio, request concurrency, and per-tenant queue depth. Negative tests should send a small compressed payload with excessive decoded frames, an extreme `n` value, and malformed sparse-embedding indices; the gateway or server should reject each before large allocation, scheduler admission, or GPU execution.
- Treat model repository writes, model-control APIs, Python backend loading, and configuration upload paths as administrative interfaces; keep them authenticated, network-restricted, logged, and separated from public inference traffic.
- Block direct internet exposure of internal IPC sockets used by serving frameworks. SGLang's May 2026 CVE-2026-7301 fired because the scheduler ROUTER socket bound to `0.0.0.0` and the framework called `pickle.loads()` on inbound messages. Default network policies should deny ingress to ZeroMQ ports; mutual authentication or even simple `--host 127.0.0.1` binding would have prevented the RCE.
- Treat image and document fetchers inside vision-language servers as SSRF risk. LMDeploy CVE-2026-33626 (April 2026) had no IP-allowlist on `load_image()`, so a `image_url=http://169.254.169.254/...` body retrieved IMDS credentials through the model server. Block link-local, RFC1918, and metadata-service ranges at the egress firewall and run the inference service under an IAM role that holds no useful metadata.
- Do not rely on framework-native API-key middleware as the only authentication layer. vLLM CVE-2026-48746 (June 2026) bypassed `VLLM_API_KEY` entirely with a crafted Host header because the middleware reconstructed URLs from untrusted input; an RFC-conforming reverse proxy (nginx, Envoy) in front of the server blocked the attack. Authenticate at the proxy and treat the framework check as defense-in-depth.
- Verify that model and code revision pinning actually covers every artifact the server loads. vLLM's "Artifact Pin Decay" (CVE-2026-47155) showed `--revision` pins silently skipping dynamic code modules, GGUF loaders, image processors, and cross-repo weights — audit what the process fetches at startup (egress logs, `strace`/eBPF on first load) rather than trusting the flag.
- Treat AI gateway and proxy configuration endpoints — MCP server registration, tool config, provider setup — as administrative command-execution surfaces. LiteLLM CVE-2026-42271 (KEV, June 2026) turned an MCP stdio config POST into OS command execution for any API-key holder. Scope these endpoints to admin roles, disable preview/experimental config APIs in production, and alert on subprocess spawns from gateway processes.
- Audit serving-container build pipelines for dependency confusion: pin hashes, avoid `--extra-index-url` with permissive index strategies (vLLM's Dockerfile shipped `UV_INDEX_STRATEGY=unsafe-best-match` against an unregistered PyPI name until 0.22.1), and build from lockfiles with `--require-hashes` where possible.
- Exercise rollback and canary procedures for serving-stack upgrades before disclosure windows; a broken inference rollback can become an availability incident even when the security patch is correct.
- Subscribe to the [Kubernetes official CVE feed](https://kubernetes.io/docs/reference/issues-security/official-cve-feed/) as part of AI platform operations. Note that the [ingress-nginx project retired in March 2026](https://kubernetes.io/blog/2025/11/11/ingress-nginx-retirement/) and receives no further releases or security fixes — any AI platform still routing model-serving ingress through it needs a migration plan to Gateway API, another maintained ingress controller, or a cloud-managed alternative (the Kubernetes announcement notes the InGate replacement project will also be retired).

### AI Operator Hardening Checks

- Treat `Model`, `InferenceService`, runtime, and model-repository CRDs as code-execution surfaces; restrict create/update rights, log changes, and require review for external model URLs.
- Reject model URLs with shell metacharacters through admission policy, and prefer exec probes that pass arguments as arrays rather than interpolating model references into `bash -c`.
- Test startup, readiness, liveness, and sidecar hooks with malicious model names, PVC query parameters, and registry references before onboarding model-serving operators.
- Pin and patch AI operators such as KubeAI, KServe, and Triton management components separately from the underlying Kubernetes and GPU driver patch cycle.

## Open Research Questions

- [x] **What's the maturity of confidential computing for GPU workloads?** — As of early 2026, NVIDIA H100 CC is GA with on-die root of trust, encrypted CPU-GPU transfers, and remote attestation (NRAS), but on confidential-GPU cloud instances without RDMA or GPUDirect, multi-GPU traffic is routed through the CPU and capped at about 3 GB/s versus 40 GB/s without CC, as reported in a 2025 benchmarking study (arXiv 2509.18886). NVIDIA says the Vera Rubin NVL72 (announced January 2026; partners expected in the second half of 2026) extends confidential computing to rack-scale — 72 GPUs, 36 CPUs, and NVLink interconnects in one trust domain with end-to-end encryption — which would be a significant step beyond H100's per-GPU model; performance claims are vendor figures. However, the TEE.Fail attack (Oct 2025) showed DDR5 memory bus interposition can break underlying CPU TEEs with <$1K hardware, and GPUHammer demonstrated practical Rowhammer attacks against GDDR6 GPU memory (USENIX Security 2025). The hardware threat surface continues to expand alongside defensive capabilities.
- [x] **How do you isolate multi-tenant GPU workloads without significant performance overhead?** — NVIDIA MIG provides hardware partition-level isolation (up to 7 instances on A100/H100) with dedicated memory, cache, and SMs per tenant. Performance isolation is strong but MIG does not encrypt — separate research (Veiled Pathways) showed four GPU-uncore leakage sources that work under MPS mode plus a PCIe covert channel across MIG instances, and GPUHammer showed Rowhammer bit flips on an RTX A6000 can tamper with another user's data in shared, time-sliced setups. Full confidential multi-tenancy requires H100 CC mode (with throughput constraints) or the upcoming Vera Rubin NVL72, for which NVIDIA claims rack-scale encryption with near-native performance (vendor claim; not yet independently benchmarked here).
- [ ] **What are the best practices for securing AI inference at the edge with limited compute?** — Apple Core ML offers compile-time model encryption (decrypted only at runtime), but this is platform-specific. Android lacks a native equivalent; teams typically use Android Keystore for key protection with custom encryption wrappers. No universal cross-platform model encryption standard exists yet. The ONNX Server for Open Enclave project provides TEE-based inference but targets server-class hardware.
- [ ] **How should hardware security requirements differ for training vs. inference infrastructure?** — Training requires higher throughput and multi-node coordination (NVLink, InfiniBand), where the NVBleed side-channel and RDMA protocol weaknesses (NeVerMore) are relevant. Inference is more deployable in TEEs due to lower data transfer volumes but faces model extraction risks. Edge inference faces unique physical access threats (BarraCUDA EM side-channel).
- [ ] **How will post-quantum cryptography affect model signing and TEE attestation chains?** — OpenSSF Model Signing v1.0 and Sigstore currently use classical cryptographic primitives. As PQC standards finalize, the model signing and TEE attestation ecosystems will need migration paths.
- [ ] **Can GPU telemetry anomaly detection reliably identify side-channel attacks?** — NVIDIA DCGM exports power, temperature, and error counters, but no published production system uses this telemetry specifically for side-channel detection. Accelerator-telemetry monitoring expectations sit in C12 rather than C4 hardware controls, so this remains an unbenchmarked detection gap with no requirement-level anchor in this chapter. Kubernetes DRA reached GA in v1.34 (locked on in v1.35) and the NVIDIA DRA driver is moving into CNCF/community ownership, which gives operators richer allocation metadata; the detection models that turn that metadata into reliable side-channel alerts remain an open gap.
- [ ] **How should organizations defend against supply chain attacks that compromise security tooling itself?** — The TeamPCP campaign (March 2026) showed that attackers can poison the very scanners and CI/CD actions that enforce supply chain integrity. Pinning GitHub Actions by commit SHA rather than mutable tags is a minimum countable defense, but the broader question — how to maintain trust in the verification chain when the verifiers are compromised — needs architectural answers beyond current SLSA and Sigstore capabilities.
- [x] **When will Confidential Containers (CoCo) with GPU support reach production readiness?** — It happened in spring 2026. NVIDIA's Confidential Containers Reference Architecture 1.0.0 is GA: H100 single-GPU passthrough and H200 Protected PCIe multi-GPU passthrough on AMD SEV-SNP or Intel TDX, with Kata, GPU Operator 26.3 (which makes Kata/CoCo a supported deployment and deprecates the standalone Kata Manager), and Trustee/NRAS composite attestation gating key release. CoCo v0.21.0 (May 29, 2026) added gRPC attestation plugins and Hopper-based CI; Red Hat documented bare-metal OpenShift CoCo with combined CPU+GPU attestation in June 2026. Remaining constraints: every GPU on a host must run in CC mode (no mixed-mode nodes), the supported hardware matrix is narrow (H100/H200), and Blackwell-generation confidential GPU support is still mostly a cloud-provider offering (for example Google Confidential VMs on G4; check current availability). C4.1.4 (confidential inference) and C4.2.2 (TEE-backed execution) now have a turnkey-adjacent Kubernetes answer, at the cost of hardware homogeneity.
- [ ] **How should inference servers themselves be hardened as part of C4.1?** — ShadowMQ (Nov 2025), the Triton RCE chain (Aug 2025), KubeAI CVE-2026-34940 (Apr 2026), LMDeploy CVE-2026-33626 (Apr 2026, exploited in 12h31m), the SGLang ZMQ pickle/dill RCEs (CVE-2026-7301/7304, May 2026), and the Triton authentication-bypass bulletin (CVE-2026-24207, May 19, 2026) showed that the biggest C4.1 gap in practice is not just running untrusted user code — it is the inference servers, AI gateways, and model-serving operators that load pickle-over-ZMQ, expose management endpoints without auth, fetch attacker-supplied URLs as a feature, turn model URLs into shell probes, or ship with `--enable-custom-logit-processor` deserializing dill objects from the network. Pwn2Own Berlin 2025 made AI infrastructure a first-class category, and Trend Micro forecasts 2,800–3,600 AI CVEs in 2026, with inference servers among the drivers it names. Current requirements (particularly 4.1.2) cover the model loader, but the inference server's own IPC, admin, control plane, Kubernetes operator surfaces, and user-supplied URL fetchers need explicit guidance — network-policy defaults, authenticated-only IPC, pickle-free deserialization inside the server process, CRD admission controls, shell-free probe construction, SSRF egress filtering, semantic resource budgets, full tensor-invariant validation, and health-based failover — not just around it. June 2026 added four more surfaces to that list: framework-native authentication middleware (vLLM CVE-2026-48746's Host-header bypass), gateway configuration APIs (LiteLLM CVE-2026-42271, an AI-gateway flaw listed in CISA KEV as exploited in the wild), remotely triggerable parser/lifetime faults that can crash Triton through 26.03 (CVE-2026-24264/24266), and vLLM inputs whose byte size looks modest while frame count, output multiplicity, or sparse-tensor indices trigger disproportionate allocation or memory-unsafe processing (CVE-2026-34755/34756/56340).
